# Roadmap

1. Baseline verified on Archipelago 0.6.8 and Silksong 1.0.30000. Seed `12345` generated solo and two-player worlds, and the client smoke test covered sending a check, receiving an item, saving, and reconnecting.
2. Reachability audit for Red Memory and The Mist verified on Silksong 1.0.30000. Fixed `RedMemorySkip` transition caching (`ToFsmState`) and suppressed the vanilla Everbloom `CreateUIMsgGetItem` popup when Everbloom is shuffled, verified automatic return to `Tut_04` (`door_ritualEnd`), and verified the `Abyss_05` flower gate before and after Everbloom delivery (`Last_Dive`). Kept the one-Silkheart requirement for The Mist after confirming Needolin requires `Silk >= 1`, drains Silk per use, and several Mist rooms have zero enemies. See [Development](DEVELOPMENT.md#the-mist-and-red-memory).
3. Map tracker filters and reachability hints verified in game. Universal Tracker matched all 13 reachable checks at one progression snapshot on seed `12345`. See [Development](DEVELOPMENT.md#map-tracker-smoke-test).
4. Expand shuffle coverage. Experimental soul, entrance, and traversal modes passed Act 1 generation. The combined interior preset passed an Archipelago server restart and a controlled five-flea Silksong test covering item delivery, offline save load, a coupled doorway, and goal reporting. A fresh save on seed `54321` verified Mossgrub soul gating and the left Cling Grip reward through normal gameplay, then reported the five-flea goal to Archipelago after five controlled location checks. A full playthrough of the shuffled route remains untested. See [Development](DEVELOPMENT.md#next-playtest).
5. Own the player workflow. The Windows prereleases passed solo and multiworld generation, a live opening check, cross-player item delivery, and reconnect and reload after a restart. The latest [playtest prerelease (`v0.5.5-rc.6`)](https://github.com/Decryptu/silksong-decrypted/releases/tag/v0.5.5-rc.6) favors finding Ledge Grab before Cling Grip when both are shuffled. `v0.5.5-rc.5` adds skill ownership, traversal gate results, and progression snapshots to Playtest Reports. `v0.5.5-rc.4` turned on category map pins and reachability by default and listed known items in map pin tooltips. `v0.5.5-rc.3` named the cause when a room was generated with a different Silksong APWorld, and `v0.5.5-rc.2` added both matched packages (with `CheckIcons/` bundled and embedded), persistent per-launch session logs, one-click Playtest Report ZIP export in the F3 panel, and updated [first-party setup](SETUP.md) and checklist flows covering manual installation, hosting, joining, recovery, sharing playtest reports, and switching between Act 2 and Act 3 from the Bellhome bed. Verified the Act 3 return flow live on Silksong 1.0.30000 (pre-Act 3 gating, hold Dash + press Needolin prompt, cancel, Act 3 → Act 2 revert and Bellhart Act 2 state, save/restart persistence, and Act 2 → Act 3 restore). See [Development](DEVELOPMENT.md#bellhome-act-3-phase-toggle).
6. First-party YAML generator built at `site/yaml.html` from the shipped APWorld options and defaults (`site/yaml-schema.json` exported via `tools/export_yaml_schema.py`, verified byte-identical against Archipelago 0.6.8). Includes seven presets, `.yaml` import, incompatibility/filler-pool validation with one-click fixes, and compact or full-defaults export. Verified all seven solo presets (compact and full-defaults) plus a three-player mixed multiworld with `ArchipelagoGenerate.exe` on Archipelago 0.6.8. See [Development](DEVELOPMENT.md#first-party-yaml-generator).
7. The site redesign, branching setup checklist, and GitHub short description are in place. Verified the full setup flow (`site/index.html`) and YAML generator (`site/yaml.html`) on a clean browser profile with zero console or HTTP errors: all role/install checklist branches (Join/Host × manual/Cogfly/r2modman), checklist progress persistence and reset, direct checklist navigation to the YAML generator, presets, filters, incompatibility validation with quick fixes, `.yaml` import/download (with a downloaded YAML verified against `ArchipelagoGenerate.exe` on Archipelago 0.6.8), full reset persistence, and zero horizontal overflow across desktop (`1280x900`, `995x850`) and mobile (`390x844`) viewports. See [Development](DEVELOPMENT.md#first-party-yaml-generator).
8. Cut 1.0 once supported goals and presets pass the baseline, progression blockers are triaged, tracker behavior is documented, and players can install, configure, and troubleshoot the release from first-party resources.

## Next up

Prioritized from playtester feedback comparing us with the Hollow Knight randomizer and Archipelago mods. Every feature ships inside Silksong Decrypted: no runtime dependencies on other mods. Read how a reference mod works, then rewrite it in our own code. See [Reference mods](ECOSYSTEM.md) for the mods and licence limits.

1. Done in `v0.5.5-rc.4`: category pins and reachability are on by default (applied once to existing configs), blocked pins are small and grey, and the full map shows a short key. Next, confirm reachability accuracy on more seeds, especially with entrance randomization.
2. Done in `v0.5.5-rc.4`: map pin tooltips list each known item and its recipient, from opened shops and received hints only (never silent shop prefetches), coloured by classification and respecting trap disguises. Requested by the main playtester. A live test of the shop path itself (open a shop, then check its pin) is still pending.
3. Give bosses and other generic pins their own art. Bosses use the generic `First Time Kill` pin. Try the game's own Hunter's Journal portraits at runtime for boss and enemy checks, so nothing needs to ship as assets. Review the other categories against the Archipelago Map Mod pin set.
4. Build a bench warp into the mod. Players want Benchwarp, but installing homothety's Silksong port means six extra libraries. Extend the F4 hub warp into a menu of visited benches grouped by area, with safe respawn handling for randomized starts, the Slab, and Act 3 phases. Model it on Silksong.Benchwarp's behaviour (reimplement, LGPL) and read bench scenes and respawn markers from the game. Then add bench pins on our map that warp on selection, and optionally sync unlocked benches through Archipelago data storage like the Hollow Knight mod's `BenchSyncModule` (MIT). Once it ships, remove the `OptionalModCompatibility.cs` Benchwarp shim and fix the APWorld FAQ entry.
5. Bring over the rest of RandoMapMod's map tools. A pin selection panel that lists previewed items and costs. A progress hint key that pans to a check unlocking progression. An item compass toward reachable checks. Map modes for full map, owned areas, and mapped rooms. For entrance randomization, a pathfinder from the current room to a selected room. These are GPL-3.0 references, so re-implement rather than copy.
6. Add a built-in skin picker. Hollow Knight players liked CustomKnight. Adapt the sprite and Texture2D replacement from Patchwork and CustomKnight (both MIT) into an F3 option that loads Hornet skin packs from a folder, ideally in the existing Customizer and Patchwork pack layouts so community skins work as they are.
7. Compare our options with the Hollow Knight randomizer settings the playtester liked, and fill gaps in the YAML generator presets.
8. Evaluate publishing on Thunderstore so Cogfly and r2modman users can install Silksong Decrypted in one step. This changes the release process, so it needs the maintainer's decision first.
9. Watch homothety's first-party Silksong randomizer work (`ItemChanger.Silksong`, `ItemChanger.Core`) for solved edge cases in items, locations, quests, and Steel Soul, and reimplement what helps.
